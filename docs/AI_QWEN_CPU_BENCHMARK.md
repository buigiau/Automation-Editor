## Completed single-image run — 2026-10-18

The resumed local run produced **14/14 Golden fills and 14 sampler WAVs**.
Both the first output and cached rebuild passed validation with no errors.
There are no overlapping selected source intervals. Three fills use the
distinct-segment shortage fallback; partial shots from different seek regions
can share the conservative `unknown` shot ID.

This is **not a cold benchmark**: it reused observations, candidate regions,
Voice and media caches from earlier interrupted attempts. The model released
its memory when free RAM fell below 1.5 GiB, then automatically resumed after
6 GiB remained available for three readings. The five-minute fresh-output
target is still unproven; this resumed run exceeded it.

Manual inspection of three frames per selected interval (10%, 50%, 90%) found
the named character present in all 14 intervals. This checks sampled visual
appearance, not every video frame or speaker identity. Slots 01 and 12 contain
small characters, slot 04 is a group view, and slot 06 has several characters
turning away. All 14 Voice matches still require audio/lip-sync review;
`audio_uncertain=true` and `local_character_verified=false` remain intact.
The owned vision runner exited after completion. The cached rebuild contains
the same accepted selections as the first output. Premiere/Cubase host import
and final playback were not measured.

## Earlier gallery run — 2026-10-16

The fresh local run did **not** produce a complete Golden output within the
five-minute target. It stopped after 270.758 seconds with 7/14 structurally
accepted selections. Character recognition was visibly incorrect, so these
seven selections are not seven visually verified edits.

Configuration: `qwen3-vl:2b-instruct`, CPU with two inference threads and no GPU
offload, `until_filled`, 300-second job target, 3 FPS sampling, no fixed source
duration cap, same-shot shortage fallback enabled. The source is the supplied
Talking Tom MP4, duration 1791.208 seconds; Golden requires 14 unique fills.

The 300-second target reserves 30 seconds for validation/export. The third
classification was interrupted when the search deadline expired. No complete
edit plan or sampler bundle was exported, and the cached-output phase was not
run. The model runner was unloaded at the end. Resource samples started about
11 seconds after the job began and describe the whole machine, including other
applications; they are not isolated model consumption measurements.

Both image/prompt evaluations took approximately 87 seconds. Inference consumed
most of the time even though discovery did not scan the entire 29:51 source.
Candidate allocation and native-frame audits also contributed to wall time.
This run reused existing Voice/media caches, but candidate labels for the new
response format were generated by real local model requests.

Visual inspection of the first contact sheet exposed mislabeling: the title
card was called `gray-cat` and a sky-only cell `white-cat`. Many genuine character
cells were labeled empty. Structural duration, transition and duplicate checks
do not establish character identity or lip synchronization. All selected rows
remain `local_character_verified=false` and `audio_uncertain=true`.

Earlier attempts in the same report include RAM guards, a generator variable
shadowing error, and a 198.932-second failure where the old response format hit
its 800-token limit. The generator was fixed and the model response changed to
one short character/score/reference string per cell. New tests cover resuming
across cuts, invalid identities/scores/references, and repeated character names.
